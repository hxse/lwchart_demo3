# 每窗口指标配置

## 使用场景与设计初衷

market 当前所有窗口共享公共指标列表，不能让三十分钟图使用 RSI、四小时图使用
MACD，或让其中一个窗口只显示行情。用户希望在同一页面按窗口分别配置，并通过
URL 保存为书签，仍保持公共默认设置与轻量操作。

同周期窗口共用 MarketStream；直接对每个窗口分别调用 configure 会用后一个
窗口的列表覆盖前一个。展示配置与计算需求需要分开归属，保持共享行情请求。

## 方案对比

复制所有公共指标到每个窗口，会失去默认值统一更新的便利。缺省继承、显式覆盖
能表达独立与无指标，并只保存需要覆盖的位置，保留原有 URL 及指标写法。

按窗口复制行情流会重复请求；完全拆分计算与行情的故障模型会扩大任务。
在同身份流上计算窗口需求的去重并集，各图表读取自己的子集，可以复用现有原子
提交、增量计算、历史校验和流级故障隔离。

## 取舍结论

保留公共默认指标，在设置中用窗口 Tab 配置周期及继承／独立／无指标。
覆盖绑定窗口位置，不绑定周期；URL 使用 chart.N.indicators，缺参数继承，none
明确关闭。公共主图占比按每个窗口自己的副图数量分配。

共享流计算规范化并集，同一配置只有一个实例；每个窗口最多十二项，流的并集
上限由最大窗口数乘十二确定。计算故障继续暂停该共享流，不增加窗口专属恢复模型。
