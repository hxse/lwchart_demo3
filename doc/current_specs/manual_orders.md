# 手动 ATR 风险下单

## 范围与用户入口

`just market` 的“单”按钮打开下单浮层，按钮顺序为设置、下单、列表入口、平铺品种。
支持四向按钮栏及明暗主题。显式关闭入口直接收起，不再询问或丢弃参数；悬浮在
外部点击、打开其他浮层及切品种时收起，平铺则保持。平铺可与设置、自选浮层
共存，浮层显示在其上方；有其他浮层时 Esc 不连带关闭面板，无浮层时 Esc 关闭。
关闭按钮与再次点击下单按钮始终关闭。
图表和已发起的一轮交易不因浮层关闭而取消。

首版模式 Tab 为“固定风险金额＋ATR”，仅市价做多／做空。支持 Binance USDⓈ-M
线性永续实盘／模拟盘及 Kraken 线性永续实盘。TQ 只显示“待实现”，不启动面板
请求。现货、反向、交割、已确认双向模式和 Kraken 模拟盘不支持。

交易所、市场及环境继承图表并只读；仅首次打开默认品种取图表，默认
周期取全部窗口按实际时长的最小值。品种、周期和数值参数可改。默认 ATR14、
风险金额 1、止损 2 ATR、金额／ATR 容差各 5%、止盈距离倍数 2。
风险币种取市场 quote，不允许改币种。参数区默认 230px 保持两列，宽面板最多
四列，数字及周期输入框宽度至多 80px，不随面板拉长，品种框跨两列；可用内容
宽度不超过 160px 才退为单列。面板正文 13px、参数及参考数值 12px、辅助说明 11px；
参数、参考、日志三部分可独立折叠，首次展开，以后恢复上次状态。

六个数值参数的输入框右侧内嵌上下箭头，单击或键盘上下键按原值加／减 1；小数
精确保留，例如 1.5 加 1 为 2.5，容差每次调整一个百分点。仅输入框获得焦点且
鼠标位于该框内时，纵向滚轮上滚加 1、下滚减 1，并阻止面板随之滚动；未聚焦、
横向滚动或带修饰键时保持默认滚动／缩放行为。仍保存原始文本草稿，空值及无法解析
的半输入不能微调，也不被替换；微调只修改草稿并触发待确认状态。数值范围仍由既有
确认校验处理，不钳制或自动提交。箭头包含在 80px 内，保持统一明暗主题与焦点样式。

做多／做空参考为两个 Tab，首次默认做多，页面内保留选中方向；点击及左右方向键、
Home／End 可切换，每次只显示一个方向，不增加读取或重建订阅。两方向预览继续更新。
参考字段固定顺序为：参考入场及来源、合约数量、基础币数量、仓位名义价值、价格风险、开仓／
止损费用、金额／ATR 误差、止损／止盈、实际 ATR／止盈倍数、预计含费风险、
预计止盈净收益。

点击做多／做空市价按钮先打开确认弹窗，显示交易所、品种、环境、方向和当前
参考数量、价格、仓位名义价值、含费风险和预计止盈净收益，金额带币种并与参考区共用同一结果；
只有“确认做多／确认做空”才提交。取消下单或 Esc
只关闭确认框，不关闭下单面板、不提交入场；已发起的条件单清理不撤回。确认期间报价和参考继续更新，
资料失效时禁用确认，最终确认重新校验并冻结最新有效快照。双击也只发起一轮。
关闭面板、切交易身份、编辑参数或打开其他设置浮层时取消尚未提交的确认。

参考区有“空仓时清理只减仓条件单”和“下单前自动查询”，独立且默认开启。
清理开启时按钮为“查询并清理”，关闭时为“查询持仓”。手动按钮和开启自动查询
后的做多／做空共用一次查询入口、页面级单飞状态及展示；若同一查询在途则复用。
自动查询随确认框打开触发，弹窗立即显示，结果醒目展示空仓、已有仓位或未能确认，
列出非零／未知记录的方向、合约数量、均价、完整身份及时间。自动关闭时确认框
不查询也不显示持仓。最终确认不再查询一次。已有仓位提示可能增加、合并或抵销。

打开面板、报价、强制刷新、切换勾选不触发此操作；两项偏好不标记参数待确认，
不随参数重置改变，不进入设置／URL／存储。既有模式证据及成交后核对独立运行。
清理关闭时仅 GET，服务端单请求最多八秒、浏览器十秒；纯读取等待或失败不阻止
确认，关闭面板或切身份取消并隔离旧回包。清理开启时使用下述 POST 流程；全程
与本页入场及交易结果查询互斥，结束后的错误／跳过仅提示，仍由用户决定是否下单。
关闭确认框、面板或切身份均不取消已准入清理，页面保留最近结果和原身份，直到下一轮
查询；新身份不得冒用旧结果。清理不会恢复被撤订单，界面明确提示取消下单也不恢复。

任何参数输入修改后须点击“确认”或“取消”，手动改回原值也不解除待确认状态。
确认整体校验成功后应用草稿，失败仍锁定；取消恢复上次确认的全部参数并清除
编辑错误。待确认时下单、强制刷新、持仓和结果查询均禁用，折叠、关闭、自动行情更新
和已准入执行继续可用。没有待确认改动时确认／取消禁用。

“强制刷新”只刷新生效身份的资料、ticker 与行情，不提交草稿或继续过去的交易。
按钮旁显示距当前品种最近成功 ticker 响应的整秒数，按浏览器单调时钟计算；首次
成功前显示尚未成功刷新，失败保留成功计龄，换品种清空。接受点击后冷却 5 秒，
冷却或本次刷新在途时禁止再次触发、不排队；ticker 与已有在途请求共用。
自动每秒刷新不受手动冷却影响，也不延长冷却；关闭后停止计时和读取。

页面持有一份 OrderMemory，包含已确认参数、原始文本草稿、待确认标记、编辑错误
及参考方向 Tab、示例线显示选项、两项查询偏好、三个区域的折叠状态；关闭、重新打开或切换形式均保留，包括空输入和非法半输入。
各品种共用这份参数，不按品种建缓存；其他 tab 独立，整页刷新及关闭 tab 清空。
不用 localStorage、sessionStorage、IndexedDB 或服务端保存，交易参数也不进入 URL／TOML。
最近一轮执行及结果仍由页面持有，参数记忆不提供交易恢复保证。

自选、设置或 URL 导航改变图表完整身份时，悬浮收起、平铺保留，只更新记忆中的交易上下文
及草稿／已确认值的品种；周期和其余数值、待确认标记保留。普通关闭重开保留
面板手填的品种。平铺按新身份释放旧读取和 ATR 需求，清除示例并重新加载；新资料
就绪前禁用提交，旧响应不得覆盖新资料。取消恢复上次确认的参数，不回退旧品种。TQ 显示待实现，
若有待确认修改仍可确认／取消；不启动面板读取，旧日志不删除或改写身份。

“重置默认值”按当前图表品种、最小周期及既有常量重填草稿，标记待确认；确认
才生效，取消可恢复已确认参数。布局、宽度、折叠和执行结果不随该按钮重置。

## 悬浮、平铺与宽度

仅以下三个显示字段进入公共设置、TOML dashboard、runtime 和 URL：

| 字段 | 取值及默认 |
| --- | --- |
| order_panel_layout | floating／inline，默认 floating |
| order_panel_inline_width | 平铺宽度，正的安全整数像素，默认 230 |
| order_panel_floating_width | 悬浮宽度，正的安全整数像素，默认 230 |

面板标题按钮直接切换形式并更新 URL，不提交交易草稿。两种形式复用同一组件及
数据订阅，不重建图表；图表通过 resize 适配。设置中的修改仍点“应用”后生效。
右栏平铺顺序为图表、面板、按钮栏；左栏镜像，上下栏时面板位于图表右侧。
关闭后释放占位，重开恢复形式。两种形式分别取自己的宽度，切换时保留另一项；可用空间不足时限制
实际显示，平铺至少给图表保留 min(160px,40%)，不回写 URL 的设定值。
非法、空值、重复字段或非整数宽度由既有配置边界拒绝。
旧 order_panel_width 字段退出，不保留兼容别名；旧 URL／TOML 须替换为两项新字段。

```text
http://127.0.0.1:5174/?order_panel_layout=inline&order_panel_inline_width=230&order_panel_floating_width=480
```

URL 前后退恢复显示设置，交易草稿不随显示设置回退；整页刷新保留 URL 显示值，
交易参数重新初始化。

## 临时价格线示例

当前参考 Tab 使用横向拆分按钮，左侧主按钮未开启时为“画线示例”，开启后原位
变为“取消示例”；右侧展开止盈线、止损线、仓位线显示的多选菜单，首次全选。
仓位线为参考入场线，不是账户已有仓位线。勾选即时过滤对应线与标签，隐藏的价格
不参与自动纵轴并集，不改下单计算或参数，不触发读取、编辑锁定或新 timer。
全部不选隐藏全部线但保留已开启状态，未开启时主按钮禁用；菜单 Esc 只关闭菜单，
外部点击也收起，内部多选保持展开。选项仅在当前页面记忆，关闭／切品种／重置参数
保留，新页面全选，不写 URL 或存储。示例暂时隐藏时仍可取消。切换 Tab 清除旧方向示例，
新方向须显式开启。所有当前品种主图使用该方向已完成精度处理的参考入场、止损、
止盈价格；左侧显示“多入／多损／多盈”或“空入／空损／空盈”及价格，取消右侧
示例线标签，面板继续提示正在示例。不同周期不重算另一组价格。下单与图表的来源、交易所、市场、环境及
完整 symbol 必须一致，待确认、参考无效或执行中不能开启。

示例跟随已有预览更新，编辑中和资料暂时失效时隐藏。主动取消、面板关闭、任一
侧身份变化或点击下单均结束示例；再次报价成功也不自动开启。折叠区域保留示例。
只纳入自动纵轴显示范围，不改变时间视口或解锁手动纵轴，移除后恢复原范围计算。

市场模块只传身份及显示配置。共享图表模块独占线对象、分组、差异更新、纵轴及
清理，通过 ChartApi.setPriceLineGroup／clearPriceLineGroup 使用原生价格线。
左标签由同一图表模块的官方 series primitive 绘制，按当前价格坐标原位更新；
邻近标签错开并以短引线对应真实价格，不修改线价，不开启左价格轴。
同 ID 原位更新，未变跳过；不重建系列、不重放历史、不增加请求或定时器。
接口规范见 [共享图表更新](chart_updates.md)，旧指标参考线及 Notebook 语义保持。

## 数据、准入与生命周期

市场资料读取后端 fetch_market_info，账户费用单独读取 fetch_trading_fee，
持仓模式证据读取 fetch_positions。打开、换品种及手动刷新读取一次；提交前
服务端重新读取核对。市场／费率失败阻止入场，独立持仓读取失败保留警告。
不读取余额、不预估保证金或自动改杠杆，资金不足由交易所拒单。

市场必须明确 swap=true、linear=true、inverse=false、active=true、settle=quote，
amount_unit=contracts，contract_size_currency=base；精确乘数读取 contract_size_decimal。
市场规则使用后端的 RuleValue 四态，原始 unknown 不改成零或 unbounded。
价格／数量步长和网格起点必须已知，匹配的多条数量规则取交集，保守检查只减仓
适用性未确认的已知数量规则。已知价格／数量限制必须满足。

未知上下限、未完成的名义金额预检、空列表／null／失败导致的模式未知都显示
警告后允许提交，由交易所最终接受或拒绝。市价名义金额不能用参考入场价替代
交易所要求的标记价；本入口不补造标记价。已知 hedged=true 禁用；Binance 三腿
固定 positionSide=BOTH，保护显式 reduceOnly=true，不自动切换账户模式。

费率是账户 taker 比例，可为零或返佣负值，不能用市场默认档位或零填补缺失。
Kraken live 的 fee_lookup 凭据在 ccxt-proxy2 配置，缺失不能计算含费风险；
Kraken sandbox 无费率来源。实际扣费币种与折扣以成交记录为准。

打开后立即获取 ticker，随后每 1000ms 单飞调度；未结束则跳过节拍，不排队。
关闭、卸载或换品种取消面板读取并隔离迟到响应。做多优先 ask，做空优先 bid，
缺失才用有效 last；非法价格或反向点差拒绝整个报价。报价失败立即禁用，获取
时间超过 5 秒禁用，服务端在提交校验及入场发送前再次核对时效。

ATR 使用现有 MarketHub → MarketStream → CandleStore → IndicatorStream 的
`ATR(period, WSMA)`，包含未收盘末根。历史容量是 max(打开时 history_bars, period)，
上限 10000；同身份／周期／容量共享流和原生实例，不向图表增加 ATR 系列。
面板需求仅增加一个内部指标槽，用户十二项限制不变。非 value、非正数、预热不足、
读取／计算错误或更新时间超过 max(10 秒, 2×刷新间隔) 均不可提交。
参数修改只重新计算；手动刷新可恢复已暂停的指标，健康流不重新播种历史。

## 计算与成交后的处理

精确网格、预算和容差比较使用有理数，不用浮点 epsilon；ATR 保持现有 Number
语义，再转换为可往返十进制。输入十进制文本最多 512 字符，归一指数绝对值至多
1024；需要写出的数量和价格另检查 number 往返不改变值，匹配后端 float 边界。
有限十进制结果完整输出，非终止比例保留至少 24 位有效数字用于展示，不能反过来参与准入判断。

设 R 为风险预算、A 为 ATR、m 为止损倍数、r 为止盈倍数、E 为方向参考价、
c 为乘数、q 为合约数量、S 为止损价、T 为止盈价、f 为当前账户 taker：

```text
D = |E − S|
预计价格风险 = q × c × D
预计含费风险 = q × c × (D + E × f + S × f)
金额误差 = |预计含费风险 − R| / R
ATR 误差 = |D/A − m| / m
T 的目标价格距离 = r × D
预计止盈净收益 = q × c × |T − E| − q × c × E × f − q × c × T × f
仓位名义价值 = q × c × E
```

两项容差为 0≤值<1，边界相等通过。先满足 ATR 距离与静态价格范围，数量须同时
满足入场及双保护网格；止盈在目标两侧相邻价格格中选择合法且最近的一格。
多解优先 ATR 误差最小、金额误差最小、风险不超过 R、较小数量、较小止损价。
区间二分与剪枝避免构造整个价格空间；单位风险不正或无合法组合时明确拒绝。

入场成交后固定原 ATR／倍数／费率，按实际 filled、average 重算保护价格。
数量不再调整；部分成交不补足。仅完整且能关联本次成交的 quote 费用可替换
开仓估计，不能重复叠加订单费用和逐笔费用。成交后风险偏差只提示，合法保护
仍提交；已知保护数量／价格非法时明确保护未提交，不自动平仓。

## 一次执行与结果事实

每轮由用户明确点击触发，页面内单飞。Bun／Vite 使用同一短流程：预检与计划
比较 → 一次市价入场 → 一轮成交核实 → 按实际成交并发提交双保护 → 一轮订单／
持仓核实。每腿至多写一次，失败不重试、不补挂、不自动平仓或撤另一腿。
两张保护不是 OCO，原有净仓可合并或抵销，用户自行管理剩余挂单。

总预算 60 秒，每个后端请求最多 min(配置超时, 8 秒, 剩余预算)，浏览器等待 65 秒。
生产 Bun 对入场、结果查询、条件单清理三个交易 POST 将连接闲置超时设为 65 秒，避免默认十秒提前切断响应。
JSON 准入后不继承页面取消信号。服务退出和浏览器刷新不保证恢复，不引入
持久化任务或后台订单管理。

回执只证明提供的事实。入场终态、非零 filled、方向及均价确认后才挂保护；open
即使部分成交也不假定最终数量固定。必要时按订单 ID 查询，均价仅用完整关联
成交补出，账户旧仓均价不能代替。无订单 ID 可在一轮列表按 clientOrderId 查找。
找不到或查询失败不等于从未成交。三腿客户端 ID 为 lw＋UUID 去横线＋e/s/t。

结果分别显示受理状态 not_sent／rejected／accepted／unknown 和订单确认状态；
首次执行将保护的方向、数量、触发价及只减仓属性与提交计划核对，不完整即未确认。
后续“查询结果”只更新订单当前事实，不重算原保护计划或恢复交易流程。页面保留
最初执行反馈，新增查询错误放入核对问题；矛盾事实显示未确认并提示人工处理。
后续显示的风险和触发价格明确属于本轮提交时计划，不保证之后手动修改仍与之相同。

参考、确认、日志统一展示“仓位名义价值”“预计含费风险”“预计止盈净收益”并
标注报价币，价格风险及费用也带币种。名义价值由交易计算模块的同一精确函数从
既有计划派生，不新增 HTTP 字段；不代表保证金或账户总仓位，也不替代交易所
要求的 mark_price 等名义金额预检依据，未知规则警告保持。
日志的“本轮成交估算（提交时）”读取 submitted_plan 的实际成交数量、均价、
精确乘数、风险、收益及开仓费用来源。部分成交仅计实际数量；后续报价、编辑、
切品种、只读查询及关闭重开均不重算或覆盖这份快照。没有计划时提示暂无可用
成交估算，不拿当前预览或零值填充；保护拒单不删除估算，也不把预计净收益标为已实现利润。

## 空仓条件单清理

清理冻结当前已确认的下单身份，包含交易所、市场、实盘／模拟盘及完整 symbol，
与图表品种可不同。复用 OrderSession 有限预算，准入后不继承浏览器取消信号。
浏览器丢失响应时显示撤单可能生效，并按单调时钟锁定至本轮 65 秒执行窗口结束；不自动重试。
本页互斥和撤单前复查不能使独立交易所请求原子化，也不锁定其他客户端。

1. 读取 `fetch_positions`，只检查目标 symbol，只有成功空列表或全部已知 contracts=0
   才确认空仓。数量未知、非法或失败不视为零，多空不能净额抵销；有仓位直接跳过。
2. 空仓后读取 `fetch_open_orders`，不传 since／limit，不复用订单核对的缓存列表。
   过滤其他 symbol；身份非法或目标订单 ID 重复时失败。忽略已知终态，未终态的
   status 不明确为 open 或 reduceOnly 不明确为 true 时全部跳过并提示开仓挂单风险。
3. 仅撤 status=open、reduceOnly=true 且 triggerPrice 为正或明确条件类型的订单。
   类型忽略大小写，接受 stop、stop_market、stop_loss、stop_loss_limit、take_profit、
   take_profit_market、take_profit_limit、trailing_stop_market、stp、trailing_stop。
   普通只减仓限价单及无法确认条件类型的单保留；不限定 lwchart 客户端编号。
4. 有候选时再次读取持仓，仍确认空仓才取消。逐笔 `cancel_order`，最多并发两笔，
   每项传完整身份及 id；不传 stop、不调用 cancel_all_orders、不自动重试。
5. 撤单后重新读取挂单。逐项保留受理状态和核对结果：明确 canceled 回执且列表
   不再包含该单才显示已确认取消；稀疏 200 回执只表明受理，缺席只表示不在挂单列表，
   最终状态未确认。仍出现为 open，查询失败为 unknown。失败项及总体核对错误均展示。

持仓快照和清理结果共用一份展示组件，不改写原三腿执行日志或提交时财务快照。
清理完成不会自动入场；查询／撤单失败不自动重试，也不补挂条件单。

## 本地 HTTP 契约

| 方法与路径 | 行为 |
| --- | --- |
| GET `/api/ccxt/fetch_market_info` | 聚合市场资料、账户费率及可空模式证据 |
| GET `/api/ccxt/fetch_ticker` | 归一单品种报价及本地 observed_at |
| GET `/api/ccxt/fetch_positions` | 仅查询当前品种持仓，不撤单 |
| POST `/api/ccxt/manual-order` | 一轮市价入场和保护 |
| POST `/api/ccxt/manual-order/check` | 严格只读核对 |
| POST `/api/ccxt/manual-order/cleanup` | 查询持仓，合格空仓时清理条件单并核对 |

三个 GET 只接受 exchange_name、market、is_live、symbol 四个必填 query；重复／未知
字段拒绝。市场响应是 `{market_info, trading_fee, position_evidence, warnings, observed_at}`，
前两项保留真实后端正式字段；模式查询失败为 null，确认空列表为 []，不透出私有 info。
ticker 响应为 `{ticker:{symbol,last,bid,ask,timestamp},observed_at}`，价格是十进制
字符串或 null，时间是毫秒整数或 null。
持仓响应为 `{identity, checked_at, positions}`，记录仅含 side、contracts、entry_price，
与执行后核对共用归一入口。side 为 long／short／null；数量及均价分别为非负／正
十进制字符串或 null。按 symbol 筛选，不透传 info；上游请求使用 symbols。读取
失败或非法值返回脱敏错误，不返回假空仓；此 GET 不发订单或查询余额、挂单。

POST 必须同源 Origin、application/json，正文最多 8 KiB，不接受 query 或任意
Provider extras。Vite 保留正文及原始 Host／Origin，支持回环发布和 SSH 转发，
不信任 X-Forwarded-*。鉴权凭据仍只在服务端，写入 401 不自动重发。

清理请求只接受四项身份，不接受指定订单列表或额外字段，例如：

```json
{"exchange_name":"binance","market":"future","is_live":false,"symbol":"BTC/USDT:USDT"}
```

清理响应为 `{identity, checked_at, snapshot, outcome, message, orders, issues}`。
snapshot 为持仓响应或 null；outcome 为 skipped／empty／completed／failed，分别表示
资格不满足、无需清理、逐项尝试核对完成、读取或规划失败。completed 不保证全部撤销。
orders 每项 `{id, write_state, confirmation, error}`；write_state 沿用四态，confirmation
为 canceled／absent／open／unknown；error 和 issues 使用脱敏 `{code,message}`。
准入错误返回结构化 4xx，准入后业务失败保留已有事实并返回 200，不把 200 当作全部成功。

执行请求包含 request_id（UUID v4）、四项身份、mode="fixed-risk-atr"、side、
order_type="market"、parameters、atr_snapshot、quote_snapshot、expected。参数含
timeframe、atr_period、risk_amount、atr_multiplier、risk_tolerance、atr_tolerance、
take_profit_multiplier；金额／价格／比例均为字符串。ATR 快照含 value、bar_time、
history_bars；expected 含 amount、stop_price、take_profit_price、estimated_risk。
服务端复用同一计算，expected 变化返回 409 TRADE_PLAN_CHANGED，不能默默改数量。

校验失败在写入前返回 `{error:{code,message}}`，包括 INVALID_TRADE_REQUEST、
NOT_SUPPORTED、TRADE_DATA_UNAVAILABLE、NO_FEASIBLE_ORDER、TRADE_PLAN_CHANGED；
后端资料错误保留安全 code。已调用入场后正常返回统一为 200 结构化结果，200
不代表三腿成功。结果含 request_id、identity、submitted_plan、legs、verification、warnings。
每腿有 write_state、confirmation、client_order_id、order_id、filled、average、error，
未知数值为 null。submitted_plan 无法生成时为 null；其 contract_size 是精确乘数。

只读查询请求如下，返回 request_id、identity、observations、verification；
observations 含三腿确认事实，不重写 write_state：

```json
{
  "request_id": "11111111-1111-4111-8111-111111111111",
  "exchange_name": "binance", "market": "future", "is_live": false,
  "symbol": "BTC/USDT:USDT",
  "orders": {"entry": "entry-1", "stop_loss": "stop-1", "take_profit": null}
}
```

形状、三腿执行／拒绝／未知／部分成交、只读检查、条件单清理资格与逐项核对、
