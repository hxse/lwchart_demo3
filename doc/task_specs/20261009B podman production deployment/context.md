# Podman 生产部署

## 使用场景与设计初衷

用户希望本地与 ssh rn 都运行看盘生产容器，与 ccxt-proxy2 共用 trading-net。
宿主开发访问 127.0.0.1:5123，容器通过 ccxt-proxy2:5123 访问后端；发布仅绑定回环。
远程目录为 ~/dev/lwchart_demo3，不配置任何开机自启。
现有服务入口包含 Vite 顶层导入，配置只允许回环监听且尚无场景覆盖，需在同一正式链路扩展。

## 方案对比

保持宿主开发、生产镜像分阶段装配，能保留现有检查与调试入口，并让最终镜像只含运行产物。
远程同步白名单源码与锁文件，在目标机原生装配；两地复用相同构建和容器管理实现。
配置在运行时只读挂载，避免将鉴权材料写入镜像或开发缓存同步到远端。

## 取舍结论

采用一个独立部署任务，按配置／产物、部署编排、验证顺序完成。
本机与 rn 都是 Linux amd64；本机复用后端的 rootless Podman，rn 复用后端的 rootful Podman。
官方 Bun 1.4.2 slim 的 amd64 manifest 已核对；固定其 digest，禁止跨平台模拟构建。
本机 5174 已由宿主服务使用，本地覆盖选择发布 5175；rn 使用默认 5174。
控制命令不依赖后端凭据，真实后端账号权限不属于自动化验收；部署只检查网络连通与自身就绪。
