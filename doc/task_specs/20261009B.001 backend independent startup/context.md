# 前端独立启动

## 使用场景与设计初衷

前端镜像可以先构建并启动，后端随后上线。当前部署虽然已经生成或复用镜像，
但 start 在创建容器前探测后端，后端未运行、DNS 暂未注册或无法连接时直接失败。
这把行情服务的可用性错误地绑定到前端服务的启动顺序。

## 方案对比

将探测失败改为提示可以允许启动，但每次仍会发起后端请求，并可能等待超时。
取消默认探测则无需访问后端，直接以已有的前端自身健康接口验收容器。

## 取舍结论

取消启动过程中的默认后端探测，保留现有显式诊断工具的独立职责。
后端暂不可用只影响实际行情读取；配置、容器网络及前端自身就绪仍按既有契约校验。
原部署任务已经发布，本次在后续 change 修复，不改写其历史版本或发布书签。
