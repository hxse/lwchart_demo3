# 图表分配优化

## 任务边界

优化共享图表的末点／时间查询、图例更新、内部缺口分段，以及旧 Notebook 的
Base64 到 Blob 转换。扩展既有离线内存对照入口并同步受影响的 current spec。
所有修改在本任务独立 JJ change 内完成，不改写前置任务。

保持全部 HTTP、TOML、URL、Notebook props、图表公开接口、返回形状和错误语义。
不改变历史窗口、轮询频率、交易流程、指标算法／精度、缺口显示、快照隔离及
视口跟随；不调整正在运行的容器、依赖版本、GC 或真实后端。
本轮不重构窗口裁剪／不可变快照，不扩大到旧文件加载流程和其它定时器治理。

直接替换被优化的内部链路，不保留两套图例或时间索引。无需接口兼容包装。
停止线为：热点优化有对照证据、全部规定验证通过、已有业务行为保持。
无法证明等价或收益的候选不进入生产；不得以省内存为由弱化输入校验。

## 任务规范

### 时间线与查询所有权

SeriesTimeline 仍是图表已提交数据的唯一内部所有者，包含 whitespace 和图例状态。
在同一生命周期内按需维护有值点的有序查询视图；复用已持有的点引用，不复制整批行。
未参与查询的标准系列不预先建立引用数组；首次查询从当前已提交时间线生成，后续局部维护。
末个有值点、可用点数量、按顺序访问及不晚于目标时间的查询均走该视图。
使用端不得分别缓存数据；系列删除、重建、类型变化或 chart 销毁时一起释放。

只在 SDK 接受数据之后更新索引；增量修正值、值变缺口、缺口变值、清空及完整
替换须与现有时间线一致。保留正常尾根增量的局部更新，不能每次轮询重建整窗。
由本模块接管的系列，热路径不得调用 SDK data()；未接管的内部测试／SDK 系列
仅允许首次读取以初始化同一索引，不能形成另一长期维护链路。

光标仍只查询第一系列中的有值点：匹配不晚于源时间的数值时间，早于第一点返回
null，日期类型沿用不匹配数值光标的行为，whitespace 不成为匹配目标。
末根可见性仍使用最后有值蜡烛、原 bitmap 几何和原有视口跟随规则。
裁剪时的历史锚点与纯折线系列长度查询共用索引，保留原位置恢复和空数据语义。
新增索引不改变公开补丁的所有权，调用方修改输入不得污染已提交时间线。

### 图例与缺口绘图

LegendManager 继续统一管理所有系列、时间、OHLCV、格式器及缺口状态。根据最终
展示内容复用 DOM；同值更新不写 DOM，有变化才更新对应文字／行。隐藏、重显、
格式器变化、主题、注册清空及销毁行为保持；不缓存旧图表或无限增长的历史文本。
系列名、数值和缺口文字仍按文本安全展示；时间格式器保留既有字符串渲染。

内部缺口仍按连续有值段绘制，不能连过缺口或用零填补。主系列保留原有数据、
坐标轴、标记和图例；辅助段不参与自动缩放、图例和价格线。
对相同分段和样式复用已有系列，仅对有变化的段提交数据或选项；历史变化、缺口
出现／恢复、裁剪、显隐、主题和 Pane 移动均须正确同步。不能仅因段内只剩一个点
而改变已有点／线的可见效果；任何省略辅助段的方案须由真实 SDK 画面等价证明。
无缺口快路径不生成分段数组；分段缓存只保存当前窗口必要引用，移除即释放。

### 旧入口与性能取舍

Base64 输入保留原 atob 解码和 Blob 类型，直接写入目标 Uint8Array，省去普通
数字数组；Blob 与 ArrayBuffer 输入分支、非法 Base64 报错保持。
不更改 ZIP／CSV／Parquet 解析、预览、文件顺序或持有原 ZIP 的行为。

扩展既有 benchmark-memory，仅使用离线 fixture、独立服务与已安装浏览器，禁止
真实账户写操作。比较同一批输入下的当前版本与冻结的任务前版本；至少三轮交错
测量。新热点覆盖四图 1000／10000 根、可见性检查、光标同步、重复图例更新及
CCI 内部缺口；保留既有轮询、末根覆盖、追加裁剪、服务端默认／smol 对照。
Base64 用固定全字节循环样本比较 1 MiB 转换分配，并逐字节核对输出。
记录耗时、GC 后保留堆、累计采样分配和必要 SDK／DOM 操作计数；明确各指标口径。
显式 GC 只属于隔离诊断，生产不得增加性能统计或强制 GC。

## 公开接口与用户写法

看盘、下单、Notebook 和图表调用写法无变化。性能对照沿用唯一正式入口：

```bash
just benchmark-memory --baseline=/tmp/lwchart-allocation-baseline --runs=3
```

baseline 必须包含任务前源码、对应 dist-market、package.json、config.example.toml
及同版本依赖；当前版本也须已有配套产物。保持缺基线／产物、重复或非法参数
明确报错，不能连接生产后端补齐输入。

行为示例：三个目标时间 100、200、300 中，光标 250 匹配 200，光标 99 无匹配；
200 若为缺口则匹配 100。修正 200 为有效值后恢复匹配 200。价格及格式相同的
图例重复更新保持文本和节点；价格变化立即展示。Base64 `AAH/` 转为
字节 `[0, 1, 255]`，Blob MIME 仍为 `application/zip`。

## 测试、验证与阶段过渡

必须通过 `just check`、`just test`、`just market --build`；just test 已包含后者及
legacy 构建和声明消费，无源码新变化时无需重复构建。沿用离线全量回归并补充：

- 时间索引的完整／增量、首尾、历史更新、缺口切换、空数据、日期类型、输入
  隔离与销毁；非法补丁不能更新任何系列或索引。受控系列查询不整批调用 data()。
- 真实 SDK 多图光标匹配／离开、非匹配历史清除；已有 1／1.25／2 倍像素密度的
  可见性、单像素裁切、连续裁剪及时间锚点误差要求保持。
- 图例 OHLCV、单值、缺口、转义、格式器、显隐和注册清理；同值不重建 DOM。
- 缺口出现／恢复、单点段、首尾变化、历史修正、同值段不重写、主题／Pane／
  显隐更新和删除；使用真实 SDK 对照绘制结果，不只检查 mock 调用数。
- Base64 全字节范围、空输入、非法输入、Blob／ArrayBuffer 分支等价及旧 Notebook。
- 手动下单参数记忆、行情订阅、示例线、确认和执行流程继续由现有离线回归覆盖。

完成正式构建后运行三轮 benchmark-memory，比较终态并报告中位数与限制；性能
不设依赖机器的硬阈值，不因采样波动改业务。复用温和负载，读失败或异常超时
先定位原因，不对真实服务重试。任务无兼容桥接或暂不可用阶段，正式入口持续可用。
