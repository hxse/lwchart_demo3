# 前端独立启动

## 任务边界

取消本地和远端共享启动链路中的默认后端连通探测，使后端未运行或无法连接时，
前端镜像构建、容器启动、更新替换和重复启动均不因此失败或等待后端超时。
同步受影响的 current spec、guide 与离线测试；原任务文档保留历史设计。

保留 trading-net 配置及外部网络归属、配置覆盖、镜像准备、回环发布、只读挂载、
无开机自启、实例所有权、幂等、互斥、精确清理与失败恢复。不修改后端容器或
共享网络，不改变页面设置、鉴权和行情接口，不执行远端实际部署。

停止线：共享启动链路不调用后端，前端无后端时自身健康及静态页面可用，
行情失败仍通过现有受控错误返回；以下正式验证通过即可交付。

## 任务规范

build 与 start 不自动调用 --probe-backend 或其它后端探针，不新增自动登录、
等待后端恢复、重试或把失败降为提示的替代探测链路。显式 --probe-backend 诊断
保留原有限超时与失败语义，不属于默认部署流程。

start 仍检查有效配置、配套镜像、指定外部网络存在且启用 DNS、实例归属及更新
恢复条件。容器接入网络是 Podman 的创建条件，网络不存在时明确失败；不得自行
创建或修改后端管理的共享网络。错误提示不要求先启动后端服务。

启动验收唯一依据为候选容器运行中且自身 /healthz 在既有限时内成功；不以行情、
后端登录或上游网络状态判断前端就绪。首次启动、替换及幂等路径共用此规则。
前端自身启动失败继续清理候选并恢复旧实例；后端不可用不触发这种回滚。

后端地址仍来自运行配置，BackendClient 保留按实际行情读取才登录的链路。
无后端时 /、/healthz 和 /api/crypto/runtime 正常返回；实际行情请求按既有错误
契约返回 BACKEND_UNAVAILABLE 或 BACKEND_TIMEOUT，不暴露凭据。
后端随后恢复时，下一次正常行情请求可以继续工作，无需重新部署前端。

## 公开接口与用户写法

命令、参数及配置写法不变，无需增加跳过探测开关：

```bash
just deploy --target=local --build --start
just deploy --target=local --start
just deploy --target=remote --upload --build --start
just deploy --target=remote --start
```

后端未运行但指定共享网络存在、镜像与配置合法时，上述启动成功，输出看盘
容器就绪地址。此时可以打开设置及页面，行情区按现有行为显示后端连接错误。
网络不存在、发布端口被占用或前端自身未就绪仍明确失败并保留／恢复旧实例。

## 测试、验证与阶段过渡

在本次前向修复 change 直接替换默认探测调用，无桥接或允许失败的阶段。
正式验证使用 just check、just test。单元验证实际共享 engine/lifecycle 脚本，
覆盖 local／remote、首次构建启动、更新及幂等，并断言没有后端探测调用；
既有网络／DNS、配置、所有权及候选失败恢复的反向测试继续通过。

容器验证使用 just test-container，只访问独立临时网络中的 fixture，不访问真实
行情、SSH 或 registry。先启动没有后端的前端，验证健康、静态与 runtime，
实际行情请求得到既有受控连接错误；再启动假后端，验证两来源 API 恢复及原有
只读配置、回环映射、幂等和端口占用回滚。

测试镜像通过 just deploy --target=local --build 准备，仅构建、不启动在用实例；
镜像准备与上述只使用缓存的离线容器验证分开。不停止用户真实后端进行验证。
