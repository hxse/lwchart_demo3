# 最新窗口与 TQ 看盘

## 使用场景与设计初衷

用户用四周期图表只读看盘，希望 CCXT 和 TQ 都按最新数量加载：初始最新 1000 根，
每轮最新 5 根，时间重叠时覆盖、追加，接不上则重新加载完整窗口。
现有 since 游标、周线特殊起点和分页追赶不符合新的使用方式。

图例缺少可读时间及成交量。显示时间应默认跟随浏览器时区，可配置其他时区，
同时行情时间、拼接和光标联动始终使用 UTC 时间戳。
当前设置同时实时预览和点击应用，容易混淆；用户明确选择点击应用后才修改。

## 方案对比

最新小窗口可以在已持有数据上覆盖和追加；断开时重载满足有限窗口看盘，不需要
前端按周期推算起点或维护分页恢复。后端内部分页仍由其自身负责。

每次重算全部 EMA 并重新创建图表会增加开销和丢失视口。保存最近小窗口的 EMA
计算状态，按实际变化修正现有系列，可以正确覆盖旧根并控制日常更新开销。
裁剪只限制展示窗口，EMA 仍承接此前历史权重。对照需保留同起点完整模拟历史，
并使用独立标准结果，避免增量和全量路径共享公式错误却一起通过。
常用指标优先保存状态；不常用或状态复杂的指标允许全量计算，分别明确初始化语义。

CCXT 返回毫秒六列表，TQ 返回纳秒 records。网络适配分别处理输入，之后使用一份
行情、EMA、网格、光标和图例链路。原生 JSON 解析的 source token 支持精确纳秒整数，
无需引入另一份 SDK、日期框架或图表系统。

## 取舍结论

只保留最新数量读取与断开重载，不保留 since 回退。CCXT 为默认来源，TQ 默认
KQ.m@SHFE.rb；显示字段共用配置，来源身份各有一份 TOML 默认值。
菜单只编辑草稿，应用时提交图表与 URL；时区只格式化文字，时间真值不平移。
旧 ZIP／Notebook 场景继续复用共享组件，默认图例与静态调用保持原能力。
