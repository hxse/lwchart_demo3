# ADX 依赖补丁与计算支持

## 使用场景与设计初衷

market 已有统一指标计算和元数据展示链路，但 ADX 尚未准入。连续平盘属于合法行情，
trading-signals 8.3.0 的 DX 在波幅和方向移动均为零时先执行除法，产生 NaN；
ADX 将其送入 WSMA 后，即使恢复正常行情也不能恢复有限结果。重复请求历史不能解决。

用户明确允许 ADX 作为依赖补丁例外，希望补齐计算支持，同时继续使用同一套指标范式。

## 方案对比

继续禁用 ADX 会保留功能缺口。应用层过滤 NaN 或补零会掩盖错误且无法恢复已污染的
原生平滑状态。自研 ADX 或复制整库形成新的计算真值，与统一维护目标冲突。

Bun 的正式依赖补丁可以在原生 DX 产生 NaN 前处理精确的零波幅边界，保留原库
递推和末根替换协议。补丁随锁文件应用，开发、浏览器构建与容器可使用相同依赖。
成本是本项目须暂时维护这个版本专用的最小修复，并验证安装和构建输入不会漏掉它。

仅锁版本和验证典型数值不能发现整个 DX 文件的任意变动。对审核后的补丁产物
固定完整文件指纹，可在开发和构建前拒绝依赖漂移；数值回归继续证明状态与结果，
两者分别承担文件身份和行为验证。更新指纹需要重新审核，不能自动接受当前文件。

## 取舍结论

选用 Bun 补丁，仅改 trading-signals 8.3.0 的 DX 全零边界。ADX 继续由原生 ADX 与
WSMA 计算，使用已有参数、输出角色、副图和参考线元数据。其他指标不获得补丁例外，
通用错误规则不放宽。未来官方修复通过同样的严格准入后，移除补丁及其构建登记。
