# 指标对齐与集成验收

## 使用场景与设计初衷

同一库的完整重放和增量结果一致，能证明本项目适配与更新方式一致，但两个路径
仍可能共同使用有缺陷的库。还需要已知期望和边界样本，检查所选版本的可靠性。
单元测试也不能替代真实浏览器中的副图、元数据覆盖、设置和两个入口集成。

## 方案对比

自己再写一套公式作参考，会形成用户明确不要的重复指标实现；只测整数或最终
一个值，又容易漏掉预热、重复替换、连续裁剪和复合角色的错误。
使用原生完整重放作严格对齐基准，并用固定来源的已知结果独立核查可靠性，
能将更新路径问题与库结果问题分开定位，而不在项目中维护第二套指标算法。

## 取舍结论

库可靠性由计算阶段在生产迁移前完成准入，本阶段继承该前置，复核样本并验收浏览器
与双入口，不首次判定库能否使用。已开放指标和公共链路的必要断言失败是交付
问题；单指标确有库缺陷则保留原因和明确最小复现，暂不开放其 market 计算，
继续整体任务。不能用容差、删样本或跳过公共验证掩盖失败。
