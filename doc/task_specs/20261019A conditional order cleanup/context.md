# 空仓条件单清理

## 使用场景与设计初衷

独立提交的止盈、止损单可能在仓位归零后留下。用户希望查询当前下单品种持仓时，
顺便清除这些只减仓条件单，并在点击做多、做空时自动执行同一流程，把持仓结果放入
确认框。只进行用户触发的一轮查询／清理，不增加后台轮询。

## 方案对比

独立清理按钮会增加操作入口并重复持仓查询。查询按钮配合两个独立勾选项可以分别
控制清理和下单前自动查询，并保留原来的纯手动只读用法。

后端已有持仓、完整当前挂单查询和逐笔撤单路由。浏览器直接编排撤单容易因关闭
面板而丢失状态；本地交易服务编排一轮有限流程，可以沿用已准入写入独立于浏览器
取消的规则。现有 GET 持仓查询保留只读语义。

## 取舍结论

选用两个默认开启的勾选项，共用页面级执行状态和结果展示。清理限定为确认空仓、
没有开仓挂单、明确只减仓且明确为条件单的订单。资料不足时跳过，不靠猜测撤单。
清理包含其他客户端创建的合格订单，不能只凭 lwchart 客户端编号判断冗余。

各次交易所请求不具备原子性；撤单前复查持仓，并禁止本页入场和清理重叠。
不新增跨客户端锁、原生括号单、自动补单、自动重试或后台恢复系统。撤单失败按事实
展示，用户仍可在流程结束后自行决定是否确认下单。
