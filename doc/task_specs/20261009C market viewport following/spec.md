## 任务规范

### 状态判定

在每批数据提交前，以主蜡烛系列的最后一个真实数据点判断，不依据数据包数量或
EMA 点数。后面仍有整根隐藏 K 线时，末根同样位于绘图区右侧，可直接检查末根。
只考虑右侧裁切；左侧历史 K 线不可见不影响跟随判定。

最后一根蜡烛的实体及影线完整右边缘不超过绘图区右边界时跟随；边缘恰好贴合也
跟随。超过边界一个实际画布像素即属于历史；不取整逻辑范围以忽略部分遮挡，
不设置把真实裁切放宽为完整可见的容差。绘图区不含价格坐标轴或按钮栏。
尚无数据或未形成可视范围时，保留初始化链路，不使用空窗口判定历史。

几何计算以当前 timeToCoordinate、barSpacing 和主画布实际 bitmap／CSS 比例为输入，
集中适配锁文件中 lightweight-charts 5.2.1 的内置蜡烛宽度、像素对齐及影线宽度。
不读取 SDK 私有字段、不替换绘制器、不扫描截图作为生产判定。未形成主画布时
不强制跟随；依赖升级须验证几何与 SDK 实际绘制的一致性。

### 更新与位置不变量

跟随时保留当前右侧偏移及当前 barSpacing，不使用默认 rightOffset 覆盖用户距离。
在绘图区尺寸和用户缩放不变时，新增 N 个时间点后，旧时间点坐标减少
N × 当前 barSpacing，新的末根中心坐标等于更新前末根中心坐标。未新增时间点的
价格／成交量更新和历史修正不产生水平位移。横向间距不是蜡烛实体宽度。

窗口裁剪时数据数量可能不变，须按新窗口末尾及历史时间锚点恢复偏移，不能把
数组长度不变理解成没有新增。历史状态保留原可见时间的位置；锚点仍存在时，
允许逻辑索引随前端裁剪变化，但屏幕位置不变。锚点丢失沿用现有重载恢复规则。

蜡烛视窗恢复只调整 SDK 水平偏移，保持当前间距，协调 SDK 自动跟随，使所有
数据和最终偏移在同一次浏览器绘制前完成；不叠加相对移动或启动平滑动画。
SDK 尚未在下一帧应用偏移时，同一帧后续批次继承已请求的视窗。SDK 已应用
偏移或用户拖动／缩放后重新以实际视窗为准，不积累多批次补偿误差。
小数间距使用 SDK 坐标，不人工取整 CSS 位移。实际 bitmap 绘制遵循 SDK 的像素
对齐：坐标位移检验不得用允许额外一格或一 CSS 像素漂移的断言替代。

数据校验及失败语义沿用 current spec；非法批次在任何数据或视窗变化前报错。

## 公开接口与用户写法

不新增设置、URL 参数或用户操作。原 replaceSeriesData／updateSeriesData 接口不变。

用户在最新位置留下右侧空白或将最新蜡烛完整贴边：新 K 线占据原末根位置，
旧 K 线左移一个间距。用户向历史方向拖动，使最新蜡烛右侧被裁掉约 1/3 或完全
移出绘图区：追加行情保持正在查看的历史位置。拖回完整显示末根后自动恢复跟随。
